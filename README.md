# PLC Digital Twin Studio

ブラウザ内でCSVを解析し、デバイスのクロスリファレンスと基本PLC命令のスキャンを試せるReact / TypeScript製MVPです。教育用モデルであり、実機との完全一致や実設備の安全性を保証しません。

## 開発

Node.js 24 / npmを使用します。

```sh
npm ci
npm run dev
npm run test
npm run lint
npm run build

# ブラウザ統合テスト（任意の開発環境でも実行可能）
npx playwright install --with-deps chromium
npm run test:e2e
# 既存Chromiumを使う場合:
# CHROMIUM_PATH=/usr/bin/chromium npm run test:e2e
```

npmのホームキャッシュへ書込めないクラウド環境では `npm ci --cache /tmp/plc-npm-cache` を使用してください。既存チェックアウトを利用し、明示指示がない限りworktreeは作成しません。

## 操作

1. 初期表示のbasic_andサンプル、またはサイドバーのデモ回路を選択。
2. X入力をON/OFFにし、「1スキャン」または「連続実行」を押す。
3. Y/M/Dをモニター。停止中はY/Mの切替とDの初期値設定が可能。任意のX/Y/M/Dも追加可能。
4. クロスリファレンスのボタンで対象ステップを選択。「CSV出力」でデバイス使用箇所を保存。
5. ファイル選択またはドラッグ＆ドロップで独自CSVをローカル読込。文字コードは読込前に選択。

ファイル変更時は実行停止・メモリ初期化します。連続実行は200 msごとの論理スキャンであり、リアルタイムPLCの周期精度を再現しません。命令クリックは表示選択であり、命令単位実行やブレークポイントではありません。

## CSV対応状況（重要）

**GX Works2の実出力CSVは未検証・未対応です。** 実例が提供されていないため、列名や継続行、ステップ増分、オペランド配置を推測して対応済みとしていません。現在は独立した `sample-v1` アダプターのみ。`samples/basic_and.csv`、`self_hold.csv`、`mov_example.csv` はアプリ専用テスト形式で、GX Works2のエクスポートではありません。

```csv
step,instruction,operand,comment
0,LD,X0,入力
1,MOV,K-1 D0,条件成立時に転送
4,END,,
```

ヘッダーは上記と完全一致する必要があります。オペランドはスペース区切りで1セルに格納。ステップは非負安全整数・重複なし・昇順。元CSVの物理行番号（引用内改行も含む）とステップ番号を別々に保持します。引用符・カンマ・改行を含むコメント、CRLF/LF、UTF-8/BOM付きUTF-8に対応。UTF-8厳密デコードが失敗した場合にShift_JIS（ブラウザのCP932互換デコーダー）を試します。文字コードの自動判定は推定で、曖昧なASCIIデータや全CP932拡張文字の相互運用を保証しません。手動選択も可能です。

未知の列構成は最大8行のプレビューと診断を表示し、命令へ変換せず実行を禁止。解析不能行が1行でもあればプログラム全体の実行を禁止します。上限2 MiB / 20,000 CSVレコード（ヘッダー含む）。

実形式対応には、機密情報を除去した実CSVとGX Works2の出力設定・CPUシリーズの確認が必要です。追加手順は [docs/architecture.md](docs/architecture.md) を参照してください。

## 仮想PLCの対象仕様

特定CPUシリーズのエミュレーターではなく、限定した単純接点ネットワークのモデルです。X/Yは16進アドレス、M/D/T/Cは10進アドレスで正規化します。解析はX/Y/M/D/T/Cの直接指定を抽出します。シミュレーションはX/Y/MのビットとDのワードのみ。CPUごとのアドレス上限は適用しません。

| 命令                                                                                  | 対応範囲                                                         |
| ------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| LD / LDI                                                                              | X/Y/Mで条件演算を開始、反転接点                                  |
| AND / ANI                                                                             | 現在の条件とのAND / 反転AND                                      |
| OR / ORI                                                                              | 現在の条件とのOR / 反転OR                                        |
| OUT                                                                                   | 条件をY/Mへ毎回書込み                                            |
| SET / RST                                                                             | 条件が真のときのみY/Mを保持設定 / 解除                           |
| MOV                                                                                   | 条件が真のとき、DまたはK/H定数をDへ転送                          |
| END                                                                                   | 必須。オペランドなし。以降の命令は本MVPでは拒否                  |
| ANB / ORB / MPS / MRD / MPPなど                                                       | 未対応。実行前に拒否                                             |
| T/Cコイル、タイマー、カウンター、比較・演算、間接・インデックス・桁指定、特殊デバイス | 未対応。実行前に拒否                                             |
| BMOV                                                                                  | 解析時に範囲の開始・点数・読書区分を保持。範囲展開と実行は未対応 |

スキャン開始時にX入力イメージをメモリへ反映。その後は命令順にY/M/Dを即時更新し、後続命令から読み取れます。OUT後も演算結果は維持され、複数出力・条件付きMOVに使えます。出力命令を挟まない複数LDはブロック演算とみなし拒否します。ANB/ORBなどの未実装命令をNOP扱いしません。すべての検証をスキャン前に完了し、不正プログラムで部分書込みしません。

Dは0〜65535のビットパターンとして保持し、モニターで符号なし/符号付き（−32768〜32767）を併記します。K定数は−32768〜65535、H定数は0000〜FFFF。D初期値も同範囲の整数に制限。全初期化でX入力イメージも消去します。停電保持、CPU固有I/Oリフレッシュ、RUN移行、エラー時動作は再現しません。

複数書込み警告は参考情報であり、意図的なSET/RSTも検出します。未知命令のデバイス使用はread/writeをunknownと表示。範囲アクセスのクロスリファレンスは開始デバイスのみで、全デバイス使用数ではありません。

## 構造・セキュリティ

- `src/parser`: バイトデコード、CSV構文、明示アダプター
- `src/core`: React非依存の内部形式、検証、仮想メモリ、スキャンエンジン
- `src/analyzer`: 使用箇所、命令集計、範囲メタデータ、CSV出力
- `src/components`: 操作UI。将来のThree.js層とエンジンを共有可能
- `tests`: パーサー・解析・命令・複数スキャン・異常系のVitestテスト

File APIで読み、解析データはブラウザメモリのみで扱います。アップロード・アクセス解析・外部ログ送信・永続保存は実装していません。CSVはReactのテキストとして表示し、HTMLとして実行しません。出力CSVは引用と先頭数式文字の無効化を行います。依存はビルドへ同梱し、CDNを使用しません。Pagesにはコードと3つの公開デモCSVのみが含まれ、読込済みファイルはビルドに入りません。

## CI / GitHub Pages

CIはpush/PR時にnpm ci、lint、test、build、Chromiumでのブラウザ統合テストを実施。Pagesワークフローはmainへのpushまたは手動起動で同じ検証後にdistを配置します。相対baseによりリポジトリ配下のPagesに対応します。

**リポジトリ管理者が Settings → Pages → Source を GitHub Actions に設定する必要があります。** 本作業ではリポジトリ設定を変更せず、デプロイ自体も実施していません。PRブランチへのpushではPages公開は行われません。
