# エンジンとアダプターの境界

`Program` はステップ、命令、オペランド、コメント、物理ソース行、診断、プレビュー、エンコーディング、アダプター識別子を持ちます。UIもエンジンもCSV列位置を解釈しません。エンジンは同期関数とメモリオブジェクトだけで動き、DOM/Reactに依存しません。

実GX Works2アダプターを追加するときは、匿名化された出力ファイルをfixtureにし、出力バージョン、言語、列ヘッダー、命令の継続行、コメント、空行、文字コード、ステップの実際の位置を検証します。既知スキーマへの厳密な識別後に共通Programへ変換し、曖昧な入力は診断付きで拒否してください。sample-v1を実GX形式として再利用しないでください。

`RangeAccess` は開始デバイス、点数（不明ならnull）、read/write/unknown、元命令を保持します。BMOVは実行対象外であり、点数展開やCPU別上限、重複範囲解析は今後の課題です。

3Dを追加する場合、描画側はscan後のメモリスナップショットを購読し、入力要求を入力イメージへ送ります。描画フレーム時間をPLC命令の実行順序に使わないでください。現MVPはメインスレッド上の最大20,000レコードを扱います。大規模化時は同じcore APIをWorker内で動作させ、キャンセル・世代IDを追加します。
