# データと画面の境界

`Program` はステップ、命令、オペランド、コメント、物理ソース行、各オペランドの継続行、診断、プレビュー、エンコーディング、アダプター識別子を保持します。CSV形式の解釈はparserだけが担当します。日本語GX Works2リストの7列ヘッダーとサンプル用4列を別アダプターとして識別し、曖昧な入力は拒否します。UTF-16 BOMを優先してデコードします。

`PLC.scan(program, elapsedMs)` はスキャン用のメモリ・タイマー・エッジ履歴のコピー上で演算し、成功した場合だけ状態をコミットします。X入力イメージはスキャン開始時にコピーします。出力はスキャン内で命令順に即時更新。命令ごとの条件結果と接点評価をtraceに返します。UIはtraceを描画に使い、描画から演算を逆算しません。タイマー単位は本モデルで100ms固定、デフォルトの論理スキャン時間も100msです。

`buildLadder()` は同じブロック/分岐命令から不変のAND/OR論理木を構築し、各出力について等価回路を返します。元エディターの座標情報はCSVにないため、元配置を再現するものではありません。UIは1000命令までに表示を制限し、巨大な再帰描画を避けます。

試験盤は `src/core/plant/exam.ts` のReact非依存モデルです。`ExamPlant.advance(memory, wiring, elapsedMs)` が前回のPLC出力に基づいてパレットを移動し、`inputImage(wiring)` が端部・番号検出センサー、押ボタン、切替スイッチ、DSWをX入力へ変換します。その後PLCを1スキャン実行します。RUN中は物理入力の変化時にもelapsedMs=0で即時スキャンし、100ms周期の間に完結する短い押下・解放を捕捉します。入力イベントだけではタイマーや搬送時間を加算しません。周期スキャンとはログで区別します。

パレット位置の数値を描画へ渡し、CSSアニメーションから位置やPLC状態を逆算しません。スキャン失敗時は移動と入力イメージを取消します。

`ExamWiring` は盤側の機器名とPLCアドレスを分離します。TB端子番号は資料に基づく固定値、X/Yは利用者が指定します。割付JSONは16KiB以内、既知機器・X/Y型・正規化後のアドレス重複を検証し、適用時に一括で状態を切り替えます。元CSVから配線を推測しません。CP1の盤電源とPLC本体の状態は分離します。

汎用盤も引き続き利用でき、こちらではXを保持/モーメンタリ/NC接点へ割付します。将来の3D表示も同じモデル境界を共有できます。調査した資料と近似・未対応範囲は `docs/exam-panel-research.md` を参照してください。

`RangeAccess` は開始デバイス、点数、アクセス区分、元命令を保持します。桁指定は4〜16点へ展開、乗算先は2ワードへ展開。BMOVは開始/点数を保持するだけで実行・全範囲展開は未対応です。

追加の実GX形式を扱うときは、匿名化されたfixtureで列名、行継続、ステップ、コメント、文字コードを検証してください。受領した機密回路をリポジトリ、ビルド、CIログへコピーしないでください。
